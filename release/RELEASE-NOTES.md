# Chakra

First public release. A radial application launcher for macOS that asks for no permissions.

## Install

1. Download **`Chakra.dmg`** below and open it.
2. Drag `Chakra.app` onto the **Applications** shortcut in the same window.

   ```
    ┌────────────────────────────────┐
    │  Chakra 1.0                    │
    │                                │
    │     ◉   ──────drag─────▶  📁   │
    │   Chakra              Applications
    │    .app                        │
    └────────────────────────────────┘
   ```

3. Eject the disk image, then launch Chakra from Applications.
4. **The first launch will be blocked.** macOS will refuse to open it with a dialog titled
   **"Chakra" Not Opened**, saying *"Apple could not verify "Chakra" is free of malware
   that may harm your Mac or compromise your privacy."* The dialog offers only **Done**
   and **Move to Trash** — there is no Open button.

   That warning is accurate. Chakra is **ad-hoc signed rather than notarized**, because
   notarizing requires a paid Apple Developer account this project does not have. Apple has
   not inspected the app; you are choosing to trust this repository instead.

   To allow it:
   - Dismiss the block dialog with **Done** (not Move to Trash).
   - Open **System Settings → Privacy & Security**, and scroll to the **Security** section.
   - Click **"Open Anyway"** beside the blocked-app notice. This button is available for
     about an hour after the blocked launch; after that it disappears and you must retry
     the launch first.
   - Confirm **"Open"** in the re-prompt, then enter your login password.

   You only need to do this once per build.

If you would rather not extend that trust, **build it yourself** — that is exactly why the
build is six readable shell scripts with no dependencies:

```bash
git clone https://github.com/RudraMind/Chakra-Mac.git
cd Chakra && ./build.sh
```

## Verify the download

```bash
shasum -a 256 ~/Downloads/Chakra.dmg
```

Expected: `<SHA256_FILLED_IN_AT_RELEASE_TIME>`

**Paste the real value here before publishing.** `make-dmg.sh` writes it to
`build/Chakra.dmg.sha256`; read it with `cat build/Chakra.dmg.sha256`. Nothing fills this in
for you.

> The download is named `Chakra.dmg` for every release, so the link never changes. To tell
> which version a copy is, open it — the window title shows the version.

## Prove it came from this repository

Stronger than a checksum. One command:

```bash
gh attestation verify ~/Downloads/Chakra.dmg --repo RudraMind/Chakra-Mac
```

Expect `✓ Verification succeeded!`. This is a Sigstore build attestation generated by this
repository's CI — it proves the disk image was built here, from a specific commit, and cannot
be forged without control of the repository.

**macOS does not check this**, so the first-launch warning appears regardless. See
[`VERIFYING.md`](../VERIFYING.md) for every level of checking, including building from source
so you need trust nobody.

## What it does

- A **two-ring wheel** of app icons. The outer ring holds 4–10 apps you pin at fixed
  positions, so a slot's place becomes muscle memory. The inner ring holds 0–7 recents.
- A **floating orb** that sits above every app, on every Space, and over full-screen apps.
  Drag it anywhere; leave it near an edge and it tucks 62% off screen. The dots on its face
  are the dominant colours of your outer-ring apps, in ring order.
- Opens on `⌥Space` (configurable), by clicking the orb, or from the menu bar.
- Click to launch, `⌥`-click to quit, right-click to unpin, scroll to turn a ring,
  `1`–`8`/arrows/`Return`/`Esc` for keyboard control.
- Drag an app onto the orb or menu-bar icon to add it.
- Nineteen user-adjustable settings, every one clamped and type-checked on read.

## What makes it unusual

**No permission prompts, ever.** No Accessibility, no Screen Recording, no Automation. Two API
choices in the app exist only to honour that: Carbon `RegisterEventHotKey` instead of a global
`NSEvent` monitor, and a *local* monitor when recording a shortcut. A third avoidance —
`pkill` instead of AppleScript — is in the install script, not the app.

**No network connections.** No analytics, no crash reporting, no licence check, no update
check. There is no networking code in the project.

**No dependencies and no project file.** Six shell scripts drive `swiftc` directly. The app
icon is generated from Swift source by `make-icon.sh` rather than hand-drawn; the generated
`.icns` is committed so a fresh clone need not rebuild it.

## Known limitations

- **Not notarized** (see Install). Because the signature is ad-hoc, macOS treats every
  rebuild as a different program, so an "Open at login" registration needs re-approving
  after each build. A paid Apple Developer ID is the only fix.
- `Sources/main.swift` and `Sources/StatusItem.swift` have **no automated test coverage** —
  the first by construction, the second because the smoke tool never touches it. Both are
  checked by hand.
- The physical drag *leaving* Finder is not covered by tests. Everything the orb decides
  once a drag arrives is.
